## Recommended immediate slice (Phase B)

Ship a first-class **Matters/Cases operational API slice** on top of existing D1/D6 service primitives:

1. Add idempotent create/list endpoints for matters with tenancy + permission checks.
2. Add case-number recording endpoint wired to the existing normaliser path.
3. Persist an audit trail for matter lifecycle actions.
4. Cover with API tests (idempotency, pagination cursor, tenant isolation, permission denial, case-number outcomes).

Rationale: this closes a high-value PARTIAL area already in-tree, improves real product operability, and does not require firm-only secrets.

## NEXT PHASE (queued for follow-up agent)

Build **matter/client reporting + search-index persistence parity**:

1. Add repository-backed persistence for cross-surface reporting/search records needed to query matters, clients, and related operational events from durable storage rather than transient in-memory joins.
2. Wire reset-safe read hydration for reporting/search list endpoints so results are stable across stateless request cycles.
3. Extend emulator-backed runtime tests to prove reporting/search outputs survive in-memory resets and remain tenant-scoped with clearance enforcement.
4. Preserve existing idempotency, classification boundaries, and firm isolation while moving reporting/search paths to repository adapters.
