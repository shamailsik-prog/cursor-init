# F39 Frozen Install Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a contributor or CI runner can do a clean frozen install (`npm ci`) from the checked-in manifests on any npm that reads this lock, the package manager is pinned to CI's npm line, and a guard fails the build when a lockfile drifts from its manifest, when `npm ci` would fail, or when an install surface stops installing frozen.

**Architecture:**
- `package.json` keys the eve undici override on the version it replaces (`"undici@8.9.0"`), so npm 10 and npm >= 11.2 resolve one tree; `package-lock.json` is regenerated by npm 10.9.9.
- Both manifests pin npm: `packageManager: npm@10.9.9` and `devEngines.packageManager` `~10.9.0`, `onFail: error`.
- `ci_gates/check_lockfiles.py`: static manifest/lock/pin/install-surface checks (G-0 [18]) and, with `--npm-ci`, the pinned npm's own `npm ci --dry-run` per lockfile (a step in the gates job).

**Tech Stack:** Python 3 (guard), vitest (tests), npm 10.9.x / npm 11.19.1 via `npx` (e2e).

**Spec:** `docs/superpowers/specs/2026-10-18-f39-frozen-install-design.md`

- Never skip or weaken a test. A "must fail" case asserts the guard's own message, so a missing guard cannot satisfy it.
