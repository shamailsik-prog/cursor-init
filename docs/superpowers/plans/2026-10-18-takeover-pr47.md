2. **Lockfile.** The first merge needed none. Then npm 10.9.7 `--package-lock-only` added six
   `oxide-wasm32-wasi` inBundle entries, and did the same on main's own lockfile: that was F39's drift and was
   left alone. After #66 landed (second merge, 5c83c6d), the merged lockfile is exactly what npm 10.9.7
   regenerates (no diff), and `npm run gate:lockfiles` passes.
3. **Third and fourth merges** (7234730: F28 and the claim gate; 7749976: F31 and F28 docs). The only
   conflict, in the fourth, was two comment blocks in `gate-g0.yml`: both sides had added a path-gated job and
   reworded the same sentences. The header now names all four gated jobs, and the `changes` step lists both
   corpus-runtime (F31) and mutation-documents. Both jobs are kept unchanged. #47 adds no Python and touches
   nothing under `corpus_service/`, so F31's import contract is unaffected.
4. **CI draft guard.** The vault job gets main's `if:` (acc11eb: a draft PR runs no jobs). It is not
   path-gated: the e2e depends on the route, the spine, persistence and the vault, and a wrong path list would
   let a regression through silently. The mutation job is path-gated (fail-open), since its score moves only
   with the vault, its tests or their configuration.
5. **MinIO source.** The PR pulled `quay.io/minio/minio@sha256:14cea493…`, and as of 2026-10-18 that pull
   cannot work. `dl.min.io` answers 410 Gone for every community release. The quay.io repository answers 401
   to an anonymous pull token, as a nonexistent repository does (`quay.io/prometheus/prometheus` answers 200
   by the same method). `hub.docker.com` reports `minio/minio` "object not found". The job now builds MinIO
   from the upstream commit of the same release (`07c3a429…`, tag `RELEASE.2025-09-07T16-13-09Z`) with
   `go install`, which checks every module against the Go checksum database, and caches the binary per commit.
   Third-party images were rejected for the reason the PR gave. A different S3 server would change what the
   tests prove: MinIO verifies SigV4 and honours `If-None-Match`. Build time here was 654 s on 4 cores at
   load 25.
6. **No literal credentials in the workflow.** The job generates the MinIO user, password and document key
   per run (`openssl rand`) and masks them. This also settles the owner's gitleaks note about a test key in
   `gate-g0.yml`; that commit (f01f409) is no longer on the branch.
7. **Staying on `@aws-sdk/client-s3`.** #46 used `aws4fetch`, which has a smaller lockfile. Switching would
   rewrite the adapter and its tests and still change the lockfile. The SDK gives per-call abort signals, a
   single-attempt mode and typed HTTP metadata, which are what the fixes need.
8. **No HEAD before PUT.** The PR's HEAD-then-PUT was a race (another writer could land in between), and its
   error path re-threw raw SDK errors. `If-None-Match: *` is the immutability check. R2 lists it as supported
   for PutObject (developers.cloudflare.com/r2/api/s3/api, read 2026-10-18), and the integration suite proves
   MinIO answers 412.
9. **What counts as ambiguous.** No HTTP response (a timeout, reset or refusal) or a 5xx means the write may
   have landed. A 4xx is definite: no settle reads. A 412 is a conflict. Settle compares the whole stored
   payload, which includes a random nonce, so our own bytes cannot be confused with another writer's.
10. **Budget numbers.** The request timeout defaults to 5 s (range 50 to 8000 ms) and the settle budget to
    10 s (0 to 12000 ms). One ingest makes at most five vault calls plus the settle reads: a GET of an existing
    copy, the PUT, the verify GET, the store's rollback DELETE, and the route's DELETE when persisting the row
    fails. At the ceilings that is 5 × 8 s + 12 s = 52 s, under the route's `maxDuration = 60`. An
    out-of-range setting is a configuration error (503), not silently clamped.
11. **SDK response checksums stay on.** On a corrupted read the SDK's CRC check fails before AES-GCM does; that
    failure is classified `integrity` ("transport checksum mismatch"), not network. R2's current docs no longer
    ask SDK users to turn checksums off.
12. **Download failures are logged.** The GET route answered 500 silently. It now logs the doc id and the
    sanitised error, so tampering or an outage is visible to operators.
13. **Test hooks kept.** `__testHookFailNextDocumentObjectRead/Delete` refuse under `NODE_ENV=production` and
    are tested; the S3 suites inject the same failures through the fault proxy instead. The test-only S3
    writers (`overwriteS3PayloadForTests`, `putS3ObjectIfNoneMatch`, `ensureDocumentObjectBucketExists`) left
    the production module for `tests/helpers/s3-document-vault.ts`.

## 5. Residual risks

- **Live Cloudflare R2 was not exercised.** MinIO stands in for the S3 contract. R2-specific behaviour
  (checksum headers, `If-None-Match` under load, error codes) is taken from Cloudflare's documentation.
- **Bucket lock and versioning** (on FA-D16-001's fix list) are bucket configuration on R2, not something the
  adapter can set per object; R2 does not support the object-lock PutObject headers. They are not configured
  or tested here.
- **A PUT that lands after the settle budget** is still an orphan. It is logged with bucket and key; that is
  the agreed bound, not a cleanup.
- **Legacy `fs://` rows** cannot be read in production (by design). There is no migration tool.
- **MinIO is archived upstream** (no security fixes). It runs only inside CI, on 127.0.0.1, with per-run
  credentials.
- **`forcePathStyle` is unobservable in tests.** With an IP endpoint the SDK always uses path style.
