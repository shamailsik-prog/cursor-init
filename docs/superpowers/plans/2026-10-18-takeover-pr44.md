# Takeover of PR #44 (F01 re-audit follow-up, F12 firm-scoped queries)

**Branch:** `cursor/remediate-f01-f02-followup` (Cursor draft, idle since 2026-10-14, conflicted with main).
**Taken over:** 2026-10-18, by Claude, on the owner's instruction to take decisions on the stale drafts.
**Rule followed:** merge `origin/main` into the branch with merge commits only; no rebase, amend or force-push.

## What the PR was

Four Cursor commits on top of main@2b621de, 48 files, +4671/-3808:

1. A firm-scoped repository API: every `get`/`update` takes the caller's firm; `listByFirm` and the `listBy<Field>`
   variants query `firmId` (and the field) in Firestore instead of reading the whole collection; a `bindRouteRepos`
   proxy binds the firm once per request in the routes. This is the fix of **F12** (Next Firestore repositories scan
   all tenants before filtering), although the PR named it "FA-F01-001/002".
2. `adminFirestore.ts`: the Firestore emulator is refused under `NODE_ENV=production`, and production accepts
   Application Default Credentials (the two halves of the F01 re-audit LOW on the persistence side).
3. A committee-brain validation in the console's Functions dispatch (a malformed payload gets 400 from the client and
   never falls back to the Next route): a small **F02** follow-up.
4. Session replay confinement (`getForSessionReplay`), an insecure-dev firm claim, and test changes.
5. Superseded or out-of-scope parts: a G-0 Playwright allowlist entry, a CI job split, a direct
   `@google-cloud/firestore` dependency with an `engines` bump and a regenerated lockfile, and an erratum.

The PR did **not** fix the F01 re-audit HIGH (2026-10-16): `getById` still returned `snap.data()` without the
document id, so a user provisioned by the Cloud Functions got 404 on every Next route in production.

## Decision: keep one PR (no split)

The firm-scoped API (F12) and the F01 HIGH live in the same functions (`getById`, `users.get`, `loadUserRecord`)
and the same 40-odd call sites; splitting would mean re-landing the F12 refactor twice through the same files.
The superseded and out-of-scope parts are dropped instead, which leaves one coherent slice: production identity and
persistence (F01) on firm-scoped reads (F12), plus the small F02 console follow-up.

### Rulings

1. **F12 is claimed.** Issue #30 placed the F12 follow-up with #44, and the PR's main change is F12's recommended
   correction (query `firmId` in the database, stable pagination, validated rows, no cross-tenant read). The firm-size
   bound on a complete listing stays with F37 (conflict checks materialise the firm registry).
2. **F02 is not claimed closed.** The PR adds only the committee-brain client validation; the Next-only routes listed
   on #30 remain for the later batch.
3. **The empty-firm `users.get` bootstrap stays** for the actor lookups that run before the route binds a firm
   (ops-reporting, reporting, tenancy). In firebase mode those ids are bound to the session user, whose own record the
   session has already cached; it is recorded as a residual, not widened.
4. **The memory repositories keep ignoring the firm argument** on most `get` calls (dev/test only; production refuses
   memory mode). Recorded as a residual.
