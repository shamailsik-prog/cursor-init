# Phase 3d: the AI layer core (P1 gateway in Cloud Functions)

Date: 2026-10-11. Status: rulings made under the owner's standing autonomy instruction (7 October 2026); pending the partner's signature with Erratum Set No. 2.

## Why

The build order (Phase 1 plan, "Later plans") puts the AI layer after Phase 3c: "P1 cost log, 70/90% alerts, kill switch, Opik self-hosted". P1 is "the single routing point for every AI call in the system … enforces per-firm quota and a kill switch, and logs the cost of every call" (Architecture Set v19, L947-948). Cloud Functions has no P1 code today. Phase 3a deferred every provider-calling job until P1 runs there (P3-1). O-35 waits on "P1 and self-hosted Opik run in Cloud Functions". O-13 waits on "the Cloud Functions P1 path" applying the outbound mask.

## Observe: what exists

- **Next.js P1 (transitional, E-23).**
  - `platform/p1/internalAICaller.ts` holds `callCommitteeBrain`. It refuses a missing classification. It masks the body and the purpose with `maskOutboundPII`. It applies `providerAllowedFor` (the L18 §4.6 table, `platform/p1/providerPolicy.ts`, facts in `data/provider_dpa.json`, which is empty) and `assertMinimised` at rank 3 and above. It then calls the Vercel AI Gateway through the `ai` package and masks the response.
  - It has no cost log, token capture, kill switch, budget, trace or event.
  - `app/api/p1/committee-brain/route.ts` derives the classification from the matter (a caller label may only raise it; free text is floored at `internal`). It masks the matter's party names and stores the output in `committee_outputs`.
- **Cloud Functions.**
  - The HTTP `api` is the only entry point (E-37, U-1: no onCall callables).
  - `RateKind "p1"` exists: 10 requests per minute per user (L18 §4.2, L8157).
  - `requirePermission` decides firm, D1 and job actions from `platform/p5/permissionDecision.ts`.
  - `stageAudit` writes audit rows in a transaction.
  - Events are rows in the server-only `events` collection.
  - `functions/build.mjs` bundles `@/` imports from the repo root, so `platform/p1/maskOutboundPII.ts`, `providerPolicy.ts` and `types.ts` can be reused without copying.
- **Guards.**
  - The G-0 provider guard bans provider SDK imports outside `platform/p1` and `platform/committeeBrain`.
  - `ci_gates/check_fetch_allowlist.py` bans `fetch` to a non-allowlisted host outside those prefixes and `functions/test/`.
- **Verified external contracts (2026-10-11).**
  - The Vercel AI Gateway serves an OpenAI-compatible Chat Completions endpoint at `https://ai-gateway.vercel.sh/v1/chat/completions` with `Authorization: Bearer <AI_GATEWAY_API_KEY>` (Vercel docs, "OpenAI Chat Completions API with AI Gateway").
  - Its public model list (`GET https://ai-gateway.vercel.sh/v1/models`, fetched 2026-10-11) prices `anthropic/claude-opus-5.5` at input `0.000004` and output `0.00002` USD per token. The Gateway adds no markup (Vercel docs, "AI Gateway Pricing").
  - Opik's REST reference gives `POST {base}/v1/private/traces/batch` with body `{ traces: Trace_Write[] }` and response 204. A self-hosted base defaults to `http://localhost:5173/api`; Opik Cloud is `https://www.comet.com/opik/api`. Opik validates trace ids as UUIDv7 (Opik docs, "UUIDv7 ingestion validation").

| P3-61 | **The pipeline.** `callP1` decides in this order, and the first refusal wins:<br>1. classification guard (a missing or unknown label throws; L8473);<br>2. kill switch, platform then firm (P3-66);<br>3. route: task type to model (P3-62);<br>4. outbound mask of body and purpose with the party names;<br>5. provider policy (`providerAllowedFor("ai-gateway", classification)`, plus `assertMinimised` at rank 3 and above);<br>6. price present for the model (P3-62);<br>7. budget (P3-64);<br>8. credentials present;<br>9. transport call (P3-68), then the response mask;<br>10. trace export (P3-67);<br>11. one transaction writing the usage row, the month total, any threshold alerts, the audit row and the event (P3-63, P3-65, P3-69).<br>A refusal at steps 2 to 8 makes no provider call, costs 0, and still writes steps 10 and 11 with outcome `blocked` and a fixed `blockReason`. A transport error writes outcome `failed`, reason `transport_error`, cost 0. Provider error text is never returned or stored, only logged. | L947-962 (one chokepoint); L6987 (audit every gateway decision); L8199-8201 (`ai.call.blocked`). The owner's kill switch outranks every other rule, so it is checked first. Policy is checked before budget, so a privileged call is reported as a policy refusal whatever the budget. | One extra Firestore read per call (the kill switch is read fresh). |
| P3-62 | **Routing and the cost table.**<br>• One task type this phase: `committee`, routed to `anthropic/claude-opus-5.5` through provider id `ai-gateway`. This follows the routing matrix ("drafting/opinion/counter-argument → Claude Opus", L953) and uses the current Opus on the Gateway.<br>• Prices are integers in nano-USD per token: input 4,000 and output 20,000. The table records the source and the date fetched (2026-10-11), and a unit test pins them.<br>• A model with no price is refused with `model_unpriced`, because a budget cannot be enforced on an unknown cost.<br>• Cost in micro-USD is `ceil((inputTokens × inputPrice + outputTokens × outputPrice) / 1000)`.<br>• When the response carries no usage, each side is estimated as `ceil(UTF-8 bytes / 3)` tokens and the row says `tokensEstimated: true`. A third of a byte count over-counts tokens for English and Urdu text, so the estimate errs towards the budget.<br>• Every call sends `max_tokens: 4096`. | L953, L958-959 ("per-model cost table"). The prices are the Gateway's published list price, not invented; the metered model replaces them at G-1 (O-12, L8514-8530). | Opus costs about twice Sonnet per token. The 70/90 alerts and the budget stop bound the exposure. |
| P3-63 | **The cost log.**<br>• Collection `ai_usage_logs/{auto id}`, top level, with `firmId` on every row: the Layer 18 convention and the E-42(a) precedent. This supersedes v6's nested `firms/{firmId}/aiUsageLogs` (L970-978); see E-48.<br>• One row per P1 decision, with these fields: `firmId`, `actorId` (uid or `"system"`), `matterId \| null`, `jobId \| null`, `taskType`, `provider`, `model`, `classification`, `outcome` (`ok` \| `failed` \| `blocked`), `blockReason \| null`, `inputTokens`, `outputTokens`, `tokensEstimated`, `costMicroUsd`, `fxPkrPerUsd \| null`, `costPkr \| null`, `monthKey`, `trace: { id, status }`, `createdAt`.<br>• No prompt or response text is stored in this row.<br>• Spend is counted per provider call, not per request. An idempotent HTTP replay never reaches P1. A future job attempt that calls the provider again has been billed again, so it gets its own row.<br>• If the transaction fails after a successful provider call, the result is still returned (the spend has happened) and `logger.error("p1.usage_log_failed", record)` keeps the record. | L958, L970-978, L2393-2398; L8201 (event payload). A ledger must record what was billed. | Per-call rows grow with use; a TTL or a roll-up is a later decision. |
| P3-64 | **Currency and budget.**<br>• **Currency.** Micro-USD integers are canonical, because providers bill in USD. PKR is recorded alongside, when the firm has set `pkrPerUsd`: the row stores the rate snapshot and `costPkr` to 2 dp. There is no default rate; none is invented.<br>• **Budget.** The budget is per firm per calendar month in PKT (`monthKey` `YYYY-MM`, Asia/Karachi).<br>• **Setting it.** A partner sets the amount through `setBudgetAlerts { monthlyBudgetUsd, pkrPerUsd? }`.<br>• **Fail closed.** With no budget set, every call is refused (`budget_not_set`). Once the month's spend reaches the budget, every call is refused (`budget_exhausted`) until the partner raises the budget or the month turns.<br>• **Overshoot.** The check runs before the call, so concurrent in-flight calls can overshoot. The overshoot is bounded by the per-user rate limit and `max_tokens`. | L958-959 (budget alerts, kill switch), L6162-6163 and L6332 ("PKR logging"), L4432 (billing on a "monthly cycle"). The architecture says nothing about 100%; a hard stop is the reading consistent with "cost governance". | A firm cannot use AI until a partner sets a budget, and AI stops mid-month at 100%. That is intended. The alerts at 70 and 90 give warning. |
| P3-65 | **Alerts at 70 and 90 percent.**<br>• The thresholds are fixed at 70 and 90 (L958, L8516).<br>• When a call's spend takes the month total from below a threshold to at or above it, the same transaction does four things: it creates `ai_budget_alerts/{firmId}_{monthKey}_{70\|90}` (deterministic id, `tx.create`, so each fires once per threshold per month); it stages an audit row (`ai.budget.threshold`, actor `system`); it writes event `ai.budget.threshold_crossed`; and after commit it logs `logger.warn("p1.budget_threshold", …)` for Cloud Monitoring.<br>• `getAiUsage` returns the alerts.<br>• Delivery to people is P4, which is unbuilt (O-54).<br>• Raising the budget mid-month does not re-arm a threshold already crossed that month. | L958-959, L969; alerts route through P4 (L2672-2673); the O-30 precedent for alerts without P4. | A partner who raises the budget gets no second 70% warning that month. |
| P3-66 | **Kill switch.**<br>• Two scopes:<br>  – the firm's, set by a partner through `setAiKillSwitch`, stored in `ai_config/{firmId}.killSwitch`;<br>  – the platform's, set by a platform admin (claim `platformAdmin`) through `setPlatformAiKillSwitch`, stored in `platform/p1.killSwitch`.<br>• Each is `{ disableAll: boolean, disabledModels: string[], reason, setBy, setAt }`. A request replaces the whole state; `disableAll: false` with no models re-enables. A reason is required (1 to 500 characters), and both writes are audited.<br>• P1 reads both on every call, with no cache, so a switch takes effect on the next call ("instantly", L959). Calls already in flight complete.<br>• Block reasons are `kill_switch_platform` and `kill_switch_firm`.<br>• Every provider call goes through P1 (L18 §9 rule 6, L8458), so the switch covers OCR, STT, TTS and translation when they are built. | L958-959 ("owner kill switch that disables all AI instantly (or a single model)"), L967. The platform scope is the operator's control across firms. | One read of each config per call. |
| P3-67 | **Opik tracing.**<br>• `functions/src/p1/opik.ts` exports one trace per P1 decision through Opik's REST batch endpoint (`POST {OPIK_BASE_URL}/v1/private/traces/batch`). The trace id is a UUIDv7, and it is the usage row's `trace.id` (O-35). The project is `OPIK_PROJECT_NAME`, defaulting to `sikander-p1`.<br>• Export is enabled only when all three hold: `OPIK_BASE_URL` is set; `OPIK_SELF_HOSTED_CONFIRMED` is `"true"` (L2067: the storage backend must be confirmed self-hosted before matter content is traced); and the URL's host is not `comet.com` or a subdomain of it (L1015-1017: "never a third-party cloud").<br>• **Content.** For ranks 0 to 3 the trace carries only the masked outbound body and the masked response; the masked text is the PII-scrubbed text (L8170). Rank 4 and blocked calls carry metadata only.<br>• **Metadata.** `classification`, `taskType`, `model`, `provider`, `outcome`, `blockReason`, tokens, `costMicroUsd`, `firmId`, `matterId` and the usage row id.<br>• **Fail-open.** Export has a 2-second timeout. A failed export never fails the call. The row records `trace.status` (`exported` \| `failed` \| `disabled`) and the failure is logged as `p1.trace_export_failed`. | L1000-1023 (P3), L2036-2039 (from day one), L2067, L8170, L8540; G-1: "Opik shows every call with classification and scrubbed PII" (L8484-8485). Resolves L1002 ("full prompt/response capture") against L8170 ("trace PII-scrubbed"): masked text only (E-49). | A missing trace is findable by its row status. Re-export is O-55. |
| P3-68 | **Transport.**<br>• The Vercel AI Gateway's OpenAI-compatible endpoint, called by plain `fetch` (no SDK, so no new dependency).<br>• Request: `{ model, messages: [{ role: "user", content: maskedBody }], max_tokens: 4096 }`, with a 60-second timeout (the function timeout is 120 s).<br>• Response: `choices[0].message.content`, `usage.prompt_tokens` and `usage.completion_tokens`.<br>• The key comes from `AI_GATEWAY_API_KEY`, held in Secret Manager in deployment and never in code (L962). With no key, the call is refused with `no_credentials`.<br>• The transport is injectable for tests, and the injection is refused when `NODE_ENV` is `production`.<br>• `functions/src/p1/` joins the P1 prefixes of the provider guard and the fetch allowlist. | L962, L2000-2008; the Next.js layer already chose the Gateway; one key and one DPA subject. | Per-provider keys (L2000-2006) are not used. The Gateway is one provider row in the §4.6 table, so its DPA status governs every model behind it (O-21). |
| P3-69 | **Events and audit.**<br>• Each P1 decision writes one `events` row: `ai.call.completed`, `ai.call.failed` or `ai.call.blocked`, with payload `{ traceId, task, model, classification, costMicroUsd, blockReason? }` (L8199-8201, cost in micro-USD per E-48).<br>• It also writes one `audit_log` row: action `ai.gateway.decision`, actor the caller or `"system"`, target `ai_usage_logs/<id>`, the governing classification, and a decision of `allow` or `deny` with reason `ok`, the block reason, or `transport_error` (L6987).<br>• `ai.call.requested` is not written: one row per decision carries everything a requested-and-completed pair would (E-48).<br>• Kill-switch and budget changes write their own audit rows through the HTTP operation's `CallAudit`. | L6987, L7004, L8199-8201. | Two audit rows per `committeeBrain` request: the route's access decision and the gateway decision. |
| P3-70 | **`committeeBrain`.**<br>• `POST /api/platform/brain/committeeBrain { matterId, body, purpose?, classification?, partyNames? }`.<br>• Rate kind `p1`.<br>• Permission: new action `ai.call`, matter-level (same firm, member, cleared), roles partner, associate and clerk (the Next.js route excludes client, intern and accounts).<br>• `body` is 1 to 100,000 characters. `purpose` is one of the Next.js route's fixed list, default `committee-brain`. `partyNames` holds at most 50 non-empty strings.<br>• `documentIds` is refused (`400 documents_not_supported`): documents are not in Cloud Functions yet.<br>• **Classification.** The strictest of the matter's classification, the caller's label and the `internal` floor. The caller's clearance must reach it (403 `clearance`).<br>• **Party names.** Every `name` and `names` entry of the matter's `matter_parties` rows, plus the supplied names.<br>• Calls `callP1` with task `committee`, then writes one `committee_outputs` row in the Next.js shape plus `usageLogId` and `traceId`.<br>• Returns `{ outputId, blocked, reason?, text?, classification, usage: { inputTokens, outputTokens, costMicroUsd }, traceId }`. | L965 (`committeeBrain`), the Next.js route's H1/N1/I1 rules, L8157. | None beyond P3-60. |
| P3-71 | **`getAiUsage` and `setBudgetAlerts`.**<br>• `GET /api/platform/brain/getAiUsage?month=YYYY-MM` (default: the current PKT month), partner only (`ai.usage.read`). It returns the month's budget, spend in micro-USD and PKR, calls by outcome, token totals, percent used, the alerts crossed, and both kill-switch states. It reads the month total, not the logs.<br>• `POST /api/platform/brain/setBudgetAlerts { monthlyBudgetUsd, pkrPerUsd? }`, partner only (`ai.budget.set`).<br>  – `monthlyBudgetUsd`: more than 0, at most 1,000,000, at most 2 decimal places, stored as micro-USD.<br>  – `pkrPerUsd`: more than 0, at most 10,000.<br>  – The thresholds are not configurable (P3-65). | L967-969. | None. |

## Errata and open items

- **E-48: P1 in Cloud Functions (deviations from v6 P1, L963-978).**
  - HTTP routes, not onCall (E-37).
  - Top-level `ai_usage_logs` with `firmId`, not nested.
  - `costMicroUsd` plus a PKR snapshot, not `costUSD`.
  - Separate input and output tokens, with outcome, classification, block reason and trace.
  - `setBudgetAlerts` sets the amount; the thresholds stay fixed at 70 and 90.
  - Fail-closed with no budget; a hard stop at 100%.
  - Event cost in micro-USD; no `ai.call.requested`.
- **E-49: trace content.** Masked text only for ranks 0 to 3. Metadata only for rank 4 and for blocked calls. Fail-open, with the status recorded. This resolves L1002 against L8170.
- **O-13 closes.** The Cloud Functions P1 path applies `maskOutboundPII`. Address masking stays a recorded gap.
- **O-35 narrows.** P1's `traceId` is the Opik trace id, and cost is recorded by P1. Job rows' `traceId` stays as it is until a provider-calling job exists (O-56).
