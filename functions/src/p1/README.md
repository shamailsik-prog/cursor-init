# P1 AI gateway

The single routing point for every AI call in Cloud Functions (spec `docs/superpowers/specs/2026-10-11-phase3d-p1-ai-layer-design.md`, rulings P3-60 to P3-73; errata E-48 and E-49 in `docs/architecture/ERRATUM_SET_2_PROPOSED.md`). A layer that needs a provider calls `callP1` with a classification and never calls a provider itself (Layer 18 §9, rule 6). `callP1` records every decision, allowed or refused, in `ai_usage_logs`, and the provider guard and the fetch allowlist let only `functions/src/p1/`, `platform/p1` and `platform/committeeBrain` reach a provider.

P1 is CORE, with no layer flag. The Next.js `/api/p1/committee-brain` route is the transitional path (E-23) and has no cost log, kill switch or budget; it stays until the app calls the functions route (O-53). Until then the Next.js deployment must hold no AI Gateway key (`AI_GATEWAY_API_KEY` and `VERCEL_AI_GATEWAY_API_KEY` unset), so that route stays blocked (`PHASE0_NO_CREDENTIALS`): the kill switches, the budget and the cost log below govern the Cloud Functions path only (ruling R8).

## Entry point

`callP1(request, opts?)` in `gateway.ts` is the v6 `internalAICaller`. The request carries `firmId`, `actorId` (a uid or `"system"`), `matterId | null`, `jobId | null`, `taskType` (`committee` is the only one), `classification`, `body`, `purpose` and `partyNames?`. The result carries the outcome (`ok`, `failed` or `blocked`), the block reason, the masked `text` (only when `ok`), the usage row id, the trace id, the model, the token counts, `costMicroUsd`, the masked outbound body and purpose, and `accounting` (audit F08). `accounting` is `settled` when the usage row and month total are committed. It is `pending` when they are not, and then any provider spend is still held by the call's reservation until the reconciler settles it. So whether the result is available and whether its accounting is complete are told apart. `committeeBrain` returns and stores `accounting` too.

Spend is counted per provider call, not per request. A replay of a stored 2xx never reaches P1. A same-key retry after a 5xx can: the router stores no 5xx, so a `committeeBrain` whose output write failed for good after the provider call (500) runs again and is billed again, in its own usage row (O-58). A job attempt that calls the provider again has been billed again and gets its own row.

## Pipeline order (P3-61)

The first refusal wins. A refusal at steps 2 to 8c makes no provider call, costs 0, and is still traced and logged (steps 10 and 11) with outcome `blocked` and a fixed `blockReason`.

1. Classification guard: a missing or unknown label throws, before any read or write (L8473).
2. Kill switch: the platform's, then the firm's (P3-66). Both are read fresh on every call.
3. Route: task type to model (P3-62).
4. Outbound mask of the body and the purpose, with the party names (`maskOutboundPII`).
5. Provider policy: `providerAllowedFor("ai-gateway", classification)`, and at rank 3 and above `assertMinimised` on the masked body and the masked purpose.
6. Price: the model must have one.
7. Budget: one must be set, and the call's worst case must fit beside the month's spend and the holds of its live reservations (P3-64, audit F07). This first look uses the pre-call read; step 8b decides again on fresh figures.
8. Credentials: `AI_GATEWAY_API_KEY` must be set.
8b. Reservation (audit F07). One transaction re-reads both kill switches, the month total, the firm's config and the learned request overhead (`platform/p1Overhead`) and creates `ai_reservations/{usageLogId}` holding the worst case, adding it to the month's `reservedMicroUsd`. The worst case is the input ceiling of the masked body (one token per UTF-8 byte of the largest of the body and its four Unicode normal forms, plus the model's request overhead: the larger of the cost table's, 1,024, and the one learned from a breach) plus the 4,096-token output ceiling, at the model's price (re-audit R1-D1, R2-D3; Copilot finding on PR #40). It refuses, in this order: `kill_switch_platform` and `kill_switch_firm` (a switch set after step 2's read still stops the call here, re-audit R1-D3); `budget_not_set`; `accounting_indeterminate` (the firm has a provider attempt whose lease lapsed unsettled, or a reservation the reconciler quarantined, F08); `budget_exhausted` unless spent + reserved + the new reservation is at most the budget; and `concurrency_exhausted` when the firm already holds `maxConcurrentCalls` live reservations (default 4). If the reservation cannot be written within its deadline, the call is refused `reservation_failed`. In every refusal nothing is sent.
8c. Provider attempt (audit F08). A second small transaction records `providerAttempt: { attemptedAt, outcome: "pending" }` on the reservation, only while it is still held. If that write fails, the call is refused `reservation_failed`, nothing is sent and the commit releases the hold.
9. Transport call, then the response mask. Any transport error is outcome `failed`, reason `transport_error`. It is charged when the provider may have billed it (a timeout or abort, a 2xx that is not JSON, a 2xx without usable content): the usage the response reported where it is a valid count, else the estimated input and the 4,096-token ceiling, with `tokensEstimated: true`. A non-2xx and a request that never left (a refused connection, DNS, a refused redirect) cost 0. A transport that resolves without text is billed like `gateway_no_text`; any error that is not a billable `P1TransportError` costs 0. A billed failure keeps the provider's ids like an answer does (Codex P2 on PR #40): the transport reads the request-id header before it parses the body, so a 2xx that is not JSON keeps `requestId`, and one without usable content keeps `responseId` and `requestId`; both ride on the `P1TransportError`.
9b. What the provider answered and what the call is charged go on the reservation's attempt (`outcome: "returned"`, `result`, the token counts, `costMicroUsd`), with the provider's response id (`responseId`, the body's `id`) and the Gateway's request id (`requestId`, the `x-request-id` or `x-vercel-id` header) when each is a plain id (re-audit R1-D5), for an answer and for a billed failure alike. Which request-id header the Gateway sets is to be confirmed at G-1 (O-57). This write is fail-open, and lands only while the reservation is still held, so it never rewrites the attempt of a reservation the reconciler has settled. It lets the reconciler settle at that charge if the commit fails.
10. Trace export (P3-67), fail-open.
11. One transaction: the usage row, the month total, any threshold alerts, the audit row and the event. The same transaction settles the reservation: the actual cost is added to `spentMicroUsd`, the hold leaves `reservedMicroUsd`, and the reservation takes `state: "settled"` (an ok call or a billed failure) or `"released"` (an unbilled failure, or a call refused after it reserved), with `actualMicroUsd`. A reservation the reconciler already settled is never counted twice: the commit fails on it and finds the reconciler's usage row.

No raw (unmasked) body, purpose or response text reaches the transport, a trace, a usage row, an event, an audit row or a log line. Provider error text is never returned, stored or logged: the transport throws a `P1TransportError` whose code (`gateway_timeout`, `gateway_request_failed`, `gateway_status`, `gateway_not_json`, `gateway_no_text`) and message are fixed, and the gateway logs only the code (`p1.transport_failed`). The transport refuses redirects (`redirect: "error"`), so the key and the masked body go to the Gateway URL only.

## Cost, budget and alerts

- **Model and price.** `committee` goes to `anthropic/claude-opus-5.5` through provider id `ai-gateway`. Prices are integer nano-USD per token (input 4,000, output 20,000), with their source and the date fetched (2026-10-11) in `costTable.ts`. Each priced model also carries its request overhead (`inputOverheadTokens`, 1,024 for Opus) and whether that figure has been measured against the provider (`inputOverheadVerified`, false until G-1). The routing and price tables are frozen. A model with no entry, no price or no overhead is refused `model_unpriced` before anything is reserved or sent (fail closed, Copilot finding on PR #40). Every call sends `max_tokens: 4096`.
- **Cost.** In micro-USD, `ceil((inputTokens x inputPrice + outputTokens x outputPrice) / 1000)`. When the response carries no usage, each side is estimated as `ceil(UTF-8 bytes / 3)` tokens and the row says `tokensEstimated: true`: the input from the masked body that was sent, the output from the raw response, because masking shortens it and the provider billed the raw length. The raw text is used for that count only; the masked text is the only one returned, stored, traced or logged. A failed call the provider may have billed is charged too (step 9), and moves the month's spend and token totals by the same rule as an ok call, so it can cross a threshold and counts toward `budget_exhausted`.
- **Currency.** Micro-USD integers are canonical. When the firm has set `pkrPerUsd`, the row stores the rate and `costPkr` to 2 decimal places. There is no default rate.
- **Budget (audit F07).** Per firm per PKT calendar month (`YYYY-MM`, Asia/Karachi, UTC+5). With no budget set every call is refused `budget_not_set`. The budget is a limit on spend plus holds: a call is sent only after its reservation commits, and a reservation commits only if spent + reserved + its worst case is at most the budget. Once the remainder is smaller than a call's worst case (86,128 micro-USD for a 28-byte prompt; 486,016 for a 100,000-byte ASCII one), that call is refused `budget_exhausted` until the partner raises the budget, a hold is released, or the month turns.
- **The bound, precisely (re-audit R1-D1, R2-D3; Copilot finding on PR #40).** A call's worst case is `costMicroUsd(model, bodyTokenCeiling(maskedBody) + overhead, 4096)`, where:
  - `bodyTokenCeiling` is the largest UTF-8 length of the masked body as sent and of its NFC, NFD, NFKC and NFKD forms. A byte-level tokenizer bills at most one token per byte of what it splits, and a tokenizer that normalises first may split the normal form: NFKC turns U+FDFA, 3 bytes, into 33. Taking the largest of the five is conservative; that no provider bills more for the body is [REQUIRES VERIFICATION] at G-1 (O-57).
  - `overhead` is the larger of the model's `inputOverheadTokens` in the cost table (`REQUEST_OVERHEAD_TOKENS`, 1,024: deliberately generous, since the request sends one user message and no system prompt or tools, but what a provider adds unseen is not documented; the exact figure is [REQUIRES VERIFICATION] at G-1) and the overhead learned for the model from a breach (below), the learned one counted only up to the clamp: `LEARNED_OVERHEAD_MAX_FACTOR` (4) times the table's figure, 4,096 tokens for Opus (re-audit R3-D1).
  - The provider honours `max_tokens`, so output tokens never exceed 4,096.

  Spent stays within budget unless a provider bills more input than bytes + overhead; any such breach is recorded, raises an event, and raises the overhead for later calls of that model. The raise is clamped (re-audit R3-D1): the learned overhead is platform-wide, so it never counts for more than 4 times the table's figure, which bounds what one provider report can add to every other firm's reservations to 3,072 input tokens (12,288 micro-USD at the Opus input price) per call. A breach that shows more than the clamp is an anomaly: it teaches only the clamp, and it is recorded and raised as described below. Within the bound this holds for one call or for many in flight together. The charge estimate used when no usage is reported (`estimateTokens`, bytes / 3, P3-62) is lower than the bound and is not used for the reservation.

  A provider that bills more than the bound breaks the condition, not the books:
  - its charge is still recorded in full, because it is owed;
  - the excess is recorded on the reservation (`exceededMicroUsd`, and `exceededInputTokens` when the input side passed the reservation's `reservedInputTokens`);
  - the same transaction writes the event `ai.reservation.exceeded` (`{ monthKey, reservedMicroUsd, actualMicroUsd, excessMicroUsd }`);
  - when the input side passed, the same transaction raises the model's learned overhead in `platform/p1Overhead` (server-only) to the input tokens billed less the body's ceiling, counted only up to the clamp and keeping the largest seen; every later reservation for the model adds the larger of that (again at most the clamp, whatever is stored) and the table's figure. Every raise is logged `p1.overhead_learned` at ERROR, so an operator sees each one;
  - when the overhead a breach shows is above the clamp, it is an anomaly (re-audit R3-D1): in the same transaction the reservation takes `usageAnomaly: true` and the event `ai.usage.anomaly` is written (id `{usageLogId}_usage_anomaly`, payload `{ monthKey, model, inputTokens, bodyTokens, overheadTokens, learnedTokens, clampTokens }`), and after commit `logger.error("p1.overhead_anomaly", ...)` is logged. A report that implausible (25,000,000 prompt tokens for a 28-byte body, or `Number.MAX_SAFE_INTEGER`) needs a person to look at it; it can no longer price other firms out. The cost table carries no context window per model, so there is no window check;
  - `logger.error("p1.reservation_exceeded", ...)` feeds Cloud Monitoring.

  In that case, and only then, spent can pass the budget, by the excess.
- **Concurrency (audit F07).** A firm holds at most `ai_config/{firmId}.maxConcurrentCalls` live reservations, an integer from 1 to 64, default 4 (`DEFAULT_MAX_CONCURRENT_CALLS`). A further call is refused `concurrency_exhausted`. No route sets it; it is server-set config. Within one instance a firm's reservation and commit transactions run one at a time through a per-firm queue, because transactions that overlap on the month total only abort each other. Across instances the transactions contend, and each one's re-read keeps the budget whatever the interleaving.
- **Time budget (Codex P1 on PR #40).** The whole committeeBrain request fits the 120 s `api` timeout, checked at import by `assertOperationTimeBudget`: the call's phases after its first reads (`CALL_WORST_CASE_MS`, 99 s: the reservation 5 s plus one attempt in flight 3 s, the attempt record 2 s, the transport 60 s, the attempt outcome 2 s, the trace 2 s, the commit 20 s plus one attempt in flight 5 s), plus the handler's own work (`COMMITTEE_HANDLER_OVERHEAD_MS`, 16 s: eight store or Auth round trips before the call at 1 s each, then the `committee_outputs` write with its 3 s deadline and one 2 s attempt in flight, then the Idempotency-Key completion, 3 s), must be at most the timeout less a 5 s margin (`REQUEST_TIMEOUT_MARGIN_MS`). 99 + 16 = 115 = 120 - 5. To fit, the commit's share fell from 30 + 10 s to 20 + 5 s and the reservation's attempt slack from 5 s to 3 s; the transport keeps its 60 s. The pre-call allowance is enforced (re-audit R3-D2, `PRE_CALL_ALLOWANCE_MS`, 8 s): measured on the real clock from when the router received the request (`session.startedAtMs`), and checked by `callP1` after its first reads and before step 8b. Past it, nothing is reserved, sent or written, `callP1` throws `P1PreCallDeadlineError` (`retryable`), and committeeBrain answers 503 `precall_deadline`, which releases the Idempotency-Key so the same request may be retried. A read that hangs is still not cut off, but it costs nothing, and no paid work starts that could outlive the request's timeout. The output write's retries are bounded: each try is one SDK transaction attempt (`maxAttempts: 1`), at most three tries, and no wait or try starts once it would end past `OUTPUT_WRITE_DEADLINE_MS` (3 s). The reservation's lease is the function timeout plus 60 s (180 s), so no live call can still settle a reservation the reconciler acts on.
- **Alerts.** At 70 and 90 percent. The transaction that takes the month total across a threshold creates `ai_budget_alerts/{firmId}_{monthKey}_{70|90}` with `tx.create`, so each fires once per firm per month, even for parallel calls. The same transaction stages the audit row `ai.budget.threshold` (actor `system`) and the event `ai.budget.threshold_crossed`; after commit `logger.warn("p1.budget_threshold", ...)` feeds Cloud Monitoring. Raising the budget does not re-arm a threshold already crossed that month. Delivery to people is P4 (O-54).
- **Failed commit (audit F08).** If the transaction fails after a successful provider call, the result is still returned (the spend has happened), with `accounting: "pending"`, and `logger.error("p1.usage_log_failed", record)` logs the record. The spend is not lost from the books: the reservation keeps holding its worst case with its provider attempt. Once its lease lapses, the firm is refused `accounting_indeterminate` until the reconciler settles it. `accounting` is `settled` whenever the call's usage row and month total are committed. The commit paces its own retries: one SDK attempt each (`maxAttempts: 1`, so the SDK never waits, and never applies its 60 s reset after RESOURCE_EXHAUSTED), with jittered waits from 100 ms doubling to 2 s that never run past the deadline; no attempt starts 20 s after the commit starts (`COMMIT_DEADLINE_MS`, code `commit_deadline`). The 20 s window and one 5 s attempt in flight (`COMMIT_ATTEMPT_SLACK_MS`) are the commit's share of the time budget above; an import-time check enforces it. Before any failure is logged the usage row is read: a commit whose answer was lost is done, nothing is logged as failed, and the thresholds it crossed are read back from its alert docs for the `p1.budget_threshold` warning.

## Kill switch

Two scopes, each `{ disableAll, disabledModels, reason, setBy, setAt }`: the firm's in `ai_config/{firmId}.killSwitch`, the platform's in `platform/p1.killSwitch`. Both govern the Cloud Functions path only until O-53 closes (see the top of this file). The platform switch's `reason` is shown to every firm's partners in `getAiUsage` (its `setBy` is shown as `"platform"`), so it must never name a firm or a client. Only `disableAll === true` and an exact model id in `disabledModels` block. A request replaces the whole state; `disableAll: false` with no models re-enables. The reason is required (1 to 500 characters) and both writes are audited. P1 reads both on every call with no cache, so a switch takes effect on the next call; calls already in flight complete. Block reasons `kill_switch_platform` and `kill_switch_firm`.

## Events and audit

Each decision writes one `events` row (`ai.call.completed`, `ai.call.failed` or `ai.call.blocked`, payload `traceId`, `task`, `model`, `classification`, `costMicroUsd`, `blockReason?`) and one `audit_log` row (`ai.gateway.decision`, allow or deny, target `ai_usage_logs/<id>`). There is no `ai.call.requested` (E-48). A `committeeBrain` request therefore leaves three audit rows: the permission check's `ai.call` decision, the route's `ai.call` row, and the gateway's `ai.gateway.decision`. The setters audit as `ai.budget.set`, `ai.kill_switch.set` and `ai.platform_kill_switch.set`. A reservation the reconciler settles gets its missing usage row (outcome `reconciled`), the event `ai.call.reconciled` (id `{usageLogId}_reconciled`, same payload) and an audit row `ai.gateway.reconciled` (actor `system`, reason `recorded` or `worst_case`). A settlement above its hold also writes `ai.reservation.exceeded` (id `{usageLogId}_reservation_exceeded`), and one whose input shows an overhead above the clamp writes `ai.usage.anomaly` (id `{usageLogId}_usage_anomaly`, re-audit R3-D1), both classification `internal`, in the settlement's transaction.

## Lease reconciler (audit F07, F08)

`p1ReservationReconciler` (`reconciler.ts`) runs every minute in `asia-south1`. It follows the job sweeper's pattern: a pinned 45 s timeout, a 30 s wall-clock budget checked before each page and each reservation, and no retry count, because the next minute's run is its retry. It asks for lapsed records directly, so live ones never take their place however many there are or however their ids sort (re-audit R1-D2, R2-D2):
- **Pass C, the sweep, first.** A slice of 200 records still `reserved`, in document-id order from a cursor kept in `platform/p1ReconcileCursor`, wrapping to the start after the last slice. It acts only on records whose `leaseUntil` no index can find: missing, or neither a Timestamp nor a number. Those count as lapsed (the gateway always writes a Timestamp, so no live call owns such a record). Every open record is read within ceil(open / 200) runs.
- **Pass B.** Records whose lease is a number of milliseconds at or before the clock (a malformed record), oldest first.
- **Pass A.** Records whose lease is a Timestamp at or before the clock, oldest first, 100 a page and at most 5 pages a run.
- **A failed record never stops the run.** Each record is tried at most once a run, and the pass moves past it. A pass whose own query or cursor fails is logged `p1.reconcile_pass_failed` (`pass`, `code`) and the run goes on to the next pass.

Option chosen for R2-D2, and why: an indexed query for lapsed leases (Passes A and B) rather than a bigger scan or a per-firm scan. A scan in document-id order reads live records as well, so any fixed page budget can be filled by live ones; the indexed query returns only records that can be acted on, oldest first, so 500 live records cost nothing and a backlog drains in lease order. The sweep covers what the index cannot (a missing or oddly typed lease) at a bounded cost per run, and running it first means a backlog in Pass A cannot starve it.

Each lapsed reservation is handled in its own transaction that re-reads it:

- **No `providerAttempt`.** Nothing was sent. The reservation is released: its hold leaves `reservedMicroUsd` and it takes `state: "released"`, `actualMicroUsd: 0`. No usage row is written.
- **A `providerAttempt`.** The reservation is settled through the same staging as a call's commit. The charge is the one the attempt recorded after the provider answered, when it did (`reconciledFrom: "recorded"`). Otherwise it is the reserved worst case: the input ceiling and the 4,096-token ceiling, with `tokensEstimated: true` (`reconciledFrom: "worst_case"`). The usage row is the call's own id, so a late commit of a live call can never add a second row or charge. A charge above the hold takes the excess path described under the bound.
- **Malformed records.** Fields a settlement can do without are defaulted: a missing `traceId` is recorded as null, a missing actor as `system`, and an unreadable classification as the strictest label (`privileged-restricted`). A record whose firm, month (`YYYY-MM`) or hold (`reservedMicroUsd`, a non-negative integer) cannot be read fails, because settling it would mean guessing what to take off which month total.
- **Output state (Codex P2 on PR #40).** In the same transaction as a settlement or a release, the call's `committee_outputs` rows (found by `usageLogId`, this firm's only) take `accounting: "settled"`, and so does the answer stored for the request's Idempotency-Key (the reservation's `idempotencyDoc`, only when its stored answer carries this call's trace id and still says `pending`). Both writes are idempotent. A same-key replay then answers `accounting: "settled"`.
- **Transient failures are not counted (re-audit R2-D1).** A failure that a later run may not meet (contention on the firm's month total, ABORTED, UNAVAILABLE, DEADLINE_EXCEEDED, RESOURCE_EXHAUSTED, CANCELLED, UNKNOWN, INTERNAL, UNAUTHENTICATED, an expired transaction) is logged `p1.reconcile_failed` with its code and `transient: true`, and retried on the next run. It never counts toward quarantine, so a valid record is never quarantined because its firm was busy.
- **Quarantine.** Only a fault of the record itself counts: `reservation_malformed`, or any other failure that is not retryable (an invalid write, an existing usage row). Each such run is counted on the record (`reconcileFailures`, `lastReconcileError`) and logged `p1.reconcile_failed` with `transient: false`. At the third (`RECONCILE_MAX_FAILURES`) the record is quarantined: `state: "reconcile_failed"`, `quarantinedAt`, and `logger.error("p1.reconcile_quarantined", { firmId, usageLogId, failures, code })`. It keeps its hold. Its firm is refused `accounting_indeterminate` until an operator settles it: fail closed, because the firm's accounting really is unknown.

### Runbook: settling a quarantined reservation

There is no route for this. It is an operator action with the Admin SDK or the Firestore console, on `ai_reservations/{usageLogId}`, recorded in the incident log.

1. **Find it.** The `p1.reconcile_quarantined` log line names the firm and the id. `lastReconcileError` gives the code: `reservation_malformed` means a firm, month or hold that cannot be read.
2. **Use this step: repair and requeue.** It is the supported path, because the reconciler then writes every record a settlement needs, exactly as the code does.
   - Correct the unreadable field from the evidence: the `committee_outputs` row with this `usageLogId`, the month total, and the Gateway's records for `providerAttempt.responseId` or `requestId`. A field the reconciler needs is `firmId`, `monthKey` (`YYYY-MM`) or `reservedMicroUsd` (a non-negative integer, the hold the month's `reservedMicroUsd` still carries for this record).
   - Set `state` back to `"reserved"` and `reconcileFailures` to 0, and if `leaseUntil` is missing or malformed, set it to a Timestamp in the past.
   - The next minute's run settles it through the normal path (Pass A or the sweep): the usage row, the month total with its token totals and `calls.reconciled`, any threshold alert, the audit row, the event `ai.call.reconciled`, and the output and stored-answer refresh. Step 4 confirms it.
3. **Last resort, only if step 2 cannot work: settle it by hand in one transaction.** Every write below is required; leaving one out leaves the books wrong in a way nothing later corrects. Let `charge` be the micro-USD the Gateway's records show (or the reservation's `reservedMicroUsd` if they show none), `in` and `out` the token counts behind it (or `reservedInputTokens` and `reservedOutputTokens`), and `hold` the reservation's `reservedMicroUsd`.
   - If the provider was called (`providerAttempt` is present):
     - create `ai_usage_logs/{usageLogId}`: `firmId`, `actorId` (or `system`), `matterId`, `jobId`, `taskType`, `provider: "ai-gateway"`, `model`, `classification`, `outcome: "reconciled"`, `blockReason: null`, `inputTokens: in`, `outputTokens: out`, `tokensEstimated` (true unless the Gateway's records gave both counts), `costMicroUsd: charge`, `fxPkrPerUsd` and `costPkr` (from the firm's `pkrPerUsd`, or null), `monthKey`, `trace: { id: <traceId or null>, status: "unknown" }`, `reconciledFrom: "manual"`, `createdAt`;
     - on `ai_usage_months/{firmId}_{monthKey}`, increment `spentMicroUsd` by `charge`, `inputTokens` by `in`, `outputTokens` by `out` and `calls.reconciled` by 1, and decrement `reservedMicroUsd` by `hold`; set `updatedAt`;
     - set the reservation to `state: "settled"`, `actualMicroUsd: charge`, `settledAt`, `settledBy: "operator"`, and `exceededMicroUsd: charge - hold` when `charge` is above `hold`;
     - create `events/{usageLogId}_reconciled`: `name: "ai.call.reconciled"`, `firmId`, `payload: { traceId, task, model, classification, costMicroUsd: charge }`, `classification`, `occurredAt`, `idempotencyKey: "{usageLogId}:reconciled"`;
     - when `charge` is above `hold`, also create `events/{usageLogId}_reservation_exceeded` (`name: "ai.reservation.exceeded"`, `payload: { monthKey, reservedMicroUsd: hold, actualMicroUsd: charge, excessMicroUsd: charge - hold }`, `classification: "internal"`);
     - when the month's spend crosses 70 or 90 percent of the budget and `ai_budget_alerts/{firmId}_{monthKey}_{70|90}` does not exist, create it, with its `ai.budget.threshold` audit row and its `ai.budget.threshold_crossed` event, as `stage` in gateway.ts does;
     - write an `audit_log` row `ai.gateway.reconciled`: actor the operator's uid, target `ai_usage_logs/{usageLogId}`, the reservation's classification, decision `allow`, reason `manual`.
   - If the provider was never called (no `providerAttempt`): decrement the month's `reservedMicroUsd` by `hold`, and set the reservation to `state: "released"`, `actualMicroUsd: 0`, `settledAt`, `settledBy: "operator"`. No usage row, event or charge.
   - Either way, set `accounting: "settled"` on the `committee_outputs` rows with this `usageLogId`, and on `idempotency_keys/{idempotencyDoc}` set `response.body.accounting` to `"settled"` when its stored answer carries this call's `traceId`.
4. **Confirm.** The firm's next call must no longer be refused `accounting_indeterminate`, `getAiUsage` must count the call under `calls.reconciled` (when the provider was called), and the month's `reservedMicroUsd` must have dropped by `hold`.

### Runbook: resetting a learned request overhead (re-audit R3-D1)

A learned overhead raises every firm's reservations for its model, up to the clamp (4 x the cost table's `inputOverheadTokens`, 4,096 tokens for Opus). An operator resets it when the breach that taught it is judged wrong: a `p1.overhead_anomaly` or `p1.overhead_learned` log line, or an `ai.usage.anomaly` event, that the Gateway's records for the attempt's `responseId` or `requestId` do not bear out.

- **Who.** A platform operator with Admin SDK or Firestore console access to production, never a firm user. `platform/p1Overhead` is server-only: `firestore.rules` denies every client read and write through the catch-all (`tests/firestore.rules.p1-phase3d.test.ts` proves no role of any firm, with or without `platformAdmin`, can read, write or delete it). There is no route for this.
- **How.** Delete the model's entry, `models.<key>` in `platform/p1Overhead`, where `<key>` is the model id with every character outside letters, digits, `_` and `-` replaced by `_` (`anthropic/claude-opus-5.5` is `anthropic_claude-opus-5_5`). With the Admin SDK: `update({ ["models." + key]: FieldValue.delete() })`. Deleting the whole doc resets every model.
- **Effect.** The next reservation for the model reads the table's figure again (1,024 for Opus). A later breach may raise it again, up to the clamp, and is logged at ERROR as before.
- **Record.** Note the reset, the model, the value removed and the evidence in the incident log.

The Gateway gives this code no per-request receipt, so no charge is matched against the provider's own bill here. The attempt keeps the provider's `responseId` and the Gateway's `requestId` so this can later be done per request. That remains O-57: reconcile `costMicroUsd` against the Gateway's records at G-1.

## Trace (Opik)

One trace per decision, posted to `{OPIK_BASE_URL}/v1/private/traces/batch`. The trace id is a UUIDv7 and is the usage row's `trace.id`. Ranks 0 to 3 carry the masked outbound body and the masked response; rank 4 and blocked calls carry metadata only (E-49). Export has a 2-second timeout and is fail-open: a failed export never fails the call, the row records `trace.status` (`exported`, `failed` or `disabled`) and the failure is logged as `p1.trace_export_failed`.
